### Progressive hints

#### Minimum Window Substring

- Hint 1 - small directional nudge: Treat `t` as a multiset. A window is not valid because it contains the right unique letters; it is valid only when every required count is satisfied.
- Hint 2 - relevant invariant or data-structure choice: Keep two count maps or one need map plus current counts, and track how many required characters have reached their required frequency.
- Hint 3 - high-level approach, still without code: Expand right until the window becomes valid, record the smallest valid window, then move left while validity holds; when removing left breaks a required count, resume expansion.

### Design artifact

- Timebox: 50 minutes.
- Prompt: Design a parking lot LLD model for a multi-floor lot with entry gates, exit gates, tickets, spot assignment, payments, and operational status.
- Required artifact in your own session notes: A class diagram or structured class list covering entities, services, policies, repositories, and main flows.
- Acceptance criteria:
  1. State functional requirements, non-goals, and assumptions in five bullets or fewer.
  2. Model at least these concepts: `ParkingLot`, `Floor`, `Spot`, `Vehicle`, `Ticket`, `Gate`, `Payment`, `SpotAssignmentPolicy`, and `PricingPolicy`.
  3. Show the entry flow, exit flow, and one failure path such as payment failure or no spot available.
  4. Identify three extension points and the concrete change each one protects.
  5. Defend two trade-offs: simple in-memory repositories vs persistent storage, and policy interfaces vs simpler concrete methods.

### Test

- Three to five interview-style recall/trade-off questions:
  1. What invariant does each ticket carry from entry through exit?
  2. Which classes should own mutable spot availability, and why?
  3. Where should pricing rules live if tomorrow introduces EV discounts or surge pricing?
  4. What breaks if gates directly mutate random spot objects without a coordinator service?
  5. Which parts of this design would need locking or transactions in a real concurrent system?
- Rubric or expected checkpoints: Score yourself 1-5 on requirements clarity, class responsibility boundaries, extension-point quality, main-flow completeness, and trade-off defense. Pick one weak area before logging progress.
