Hint ladder

  1. Treat the target as a multiset. Unique-letter presence is not enough.
  2. Track how many required characters have reached their required frequency.
  3. Expand until valid, record the best valid window, then shrink until removing the left character breaks validity.
Engineering - Design

Parking lot LLD model

Read 25 min: Python ABCs from the module introduction through abstractmethod, then PlantUML class diagram sections for declarative elements, relations, and relation labels.

Design 50 min: produce a class diagram or structured class list for a multi-floor parking lot with entry, exit, ticketing, spot assignment, payment, and operational status.

Review 15 min: defend extension points for pricing, allocation, payment, vehicle eligibility, and gate hardware.

Pre-reading questions: Which roles need stable abstractions? Which behavior varies first? How will the class diagram show ownership and dependency without over-modeling?

Note-taking lens: for each candidate class, write owned state, invariant, and extension pressure.

Knowledge check

  1. What invariant does each ticket carry from entry through exit?
  2. Which classes should own mutable spot availability, and why?
  3. Where should pricing rules live if tomorrow introduces EV discounts or surge pricing?
  4. What breaks if gates directly mutate random spot objects without a coordinator service?
  5. Which parts of this design would need locking or transactions in a real concurrent system?
